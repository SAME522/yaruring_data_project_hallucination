오늘 결정한 것:
9차시에서 정한 선형 회귀, 로지스틱 회귀, 의사결정트리 세 모델의 평가 결과를 한 화면에 몰아넣지 않고 따로 살펴볼 수 있도록 스트림릿 페이지를 나누기로 했다. 기존에 학습한 모델을 새로 학습시킨 것은 아니고 저장된 예측 결과와 성적표를 다시 계산해 확인했다. 학습 데이터 3,605개, 시험 데이터 902개, 난수값 42, 5겹 교차검증이라는 조건에서 군집을 포함한 로지스틱 회귀의 교차검증 Brier는 약 0.1408, 시험 Brier는 약 0.1393이었다. 질문과 관계없이 학습 데이터의 Yes 비율을 그대로 예측하는 기준선의 시험 Brier는 약 0.1481이므로 로지스틱 회귀가 확률 오차를 조금 줄인 것을 확인했다. 다만 군집을 넣은 효과는 크지 않고 경고 기준을 0.5로 놓으면 실제 Yes를 많이 놓친다는 점도 함께 확인했다. GitHub의 main/pages 폴더에 데이터 전처리, 모델 평가, 군집 ON/OFF 비교, 위험도와 오분류 분석을 각각 다른 파이썬 파일로 정리했다. 모델 평가 화면에서는 기준선과 세 모델의 차이를 비교하고, 군집 비교 화면에서는 군집 특징을 넣고 뺐을 때 점수와 혼동행렬이 어떻게 달라지는지 확인하며, 오분류 분석 화면에서는 잘못 경고한 질문과 놓친 Yes 질문을 찾아볼 수 있도록 했다. 처음에는 기존 페이지 전환 메뉴를 없애고 Streamlit의 자동 메뉴를 사용했는데 실제로 페이지 전환 탭이 보이지 않는 문제가 생겼다. 이를 수정하기 위해 main.py를 페이지 연결용으로 바꾸고 화면 위쪽에 네 페이지의 전환 메뉴가 나타나도록 구성했으며 상단 메뉴를 지원하도록 Streamlit 최소 버전도 1.46으로 변경했다. 코드의 문법과 네 페이지의 파일 경로, GitHub에 반영된 파일 내용은 확인했지만 배포된 앱의 실제 화면은 아직 확인하지 못했다.

AI가 준 것 중 고치거나 버린 것과 그 이유:
처음에는 모델 평가를 기존 main.py 한 화면에 넣는 구성이었지만 세 모델의 성적표, 군집의 효과, 틀린 질문을 따로 보기 어려워 각각의 페이지로 나누었다. 페이지를 분리하면서 기존 전환 메뉴를 제거하고 자동으로 표시되는 메뉴에 맡겼는데, 내가 사용하는 화면에서 탭이 사라졌다는 문제를 확인해 이 방법을 바꿨다. 대신 페이지 이동 경로를 main.py에 직접 지정해 화면 위쪽에서 선택하도록 수정했다. 모델 평가에서는 정확도만 높다고 좋은 모델로 판단하지 않고 확률 오차를 보는 Brier 점수와 Yes 탐지 결과를 구분했다. 시험 데이터의 정답을 보고 경고 기준을 고르는 방식도 평가 결과를 부풀릴 수 있으므로 최종 기준으로 사용하지 않기로 했다.

느낀 점:
모델 세 가지의 점수를 계산하는 것뿐 아니라 결과를 직접 비교하고 왜 틀렸는지 찾아볼 수 있게 정리하는 과정도 필요하다고 느꼈다. 특히 로지스틱 회귀가 기준선보다 조금 더 정확한 위험도 수치를 내더라도 실제 Yes를 충분히 찾아낸다는 뜻은 아니라는 점을 알게 되었다. 또 코드가 제대로 작성되어도 화면에서 페이지 이동이 되지 않으면 분석하기 불편하므로 기능을 완성한 뒤에는 실제 앱 화면까지 확인해야겠다고 생각했다.

AI 없이 내가 스스로 한 것:
모델 분석 기능을 GitHub의 새 폴더에 페이지별 파이썬 파일로 나누어 관리하자고 요청했다. 이전에 선택한 세 모델을 그대로 평가해야 한다는 방향을 유지했고, 페이지 전환 탭이 없어졌다는 문제를 직접 발견해 수정을 요청했다. 모델 성적표 검산, 페이지 코드 작성, 메뉴 수정 및 GitHub 반영은 AI의 도움을 받아 진행했으며 내가 직접 코드를 실행하거나 배포 화면을 검증했다고 기록하지 않았다.
