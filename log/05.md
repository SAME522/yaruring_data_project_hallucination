

 1. 오늘 결정한 것

HaluEval 1.0의 `general_data.json`을 대상으로 원본 데이터와 전처리 후 데이터를 비교하고, 전처리한 이유를 기초통계 및 시각화 결과를 통해 확인하기로 했다.
먼저 원본 데이터의 행·열 수, 결측치, 할루시네이션 발생 여부의 분포를 확인했다. 이후 사용자 질문을 분석하기 위해 질문의 글자 수, 단어 수, 고유 단어 수, 평균 단어 길이, 물음표 수 등의 수치형 변수를 생성했다. 또한 질문의 의미적 특징을 분석할 수 있도록 질문 군집과 단어 군집을 추가했다.

전처리 과정에서 행 수가 줄어들지 않았으므로 원본 질문 4,507개를 모두 유지했다. 열 수가 증가한 이유는 원본의 일부 열을 분석 목적에 맞게 정리하고, 질문 텍스트에서 새로운 특징을 추출했기 때문이다.
전처리 방법과 통계적 근거
질문의 길이와 단어 수를 수치화
원본의 사용자 질문은 대부분 문자열이기 때문에 질문의 특징을 수치로 비교하기 어려웠다. 따라서 질문을 단어별로 분리하고 글자 수, 단어 수, 고유 단어 수 등을 계산했다.
통계분석 결과 질문 글자 수의 중앙값은 64자, 평균은 약 75.95자였으며, 단어 수의 중앙값은 11개, 평균은 약 13.14개였다. 이를 통해 질문의 길이가 일정하지 않다는 점을 확인했고, 질문 길이가 할루시네이션 발생 여부와 관련이 있는지 분석할 수 있도록 수치형 변수로 변환했다.
결측치와 빈 값 확인
기초통계에서 일반적인 결측값으로 집계된 원본 데이터의 결측치는 0개였다. 그러나 전처리된 데이터를 추가로 확인한 결과, 원래 ID를 보관한 열에서 빈 값 1개를 발견했다.
해당 데이터에는 실제 질문이 존재하므로 삭제하지 않고, 원본 행 순서를 나타내는 `source_row`를 새로운 식별자로 사용했다. 이를 통해 분석에 필요한 정보를 유지하면서 식별자 문제를 해결했다.
이 과정에서 결측값(`NaN`)과 빈 문자열이 통계 프로그램에서 다르게 처리될 수 있다는 점도 확인했다.
이상치 확인
질문 글자 수의 중앙값은 64자였지만, 가장 긴 질문은 1,316자였다. 단어 수도 중앙값 11개에 비해 최댓값은 202개로 큰 차이를 보였다.
그러나 긴 질문이라는 이유만으로 잘못된 데이터라고 판단할 수 없으므로 해당 질문들을 삭제하지 않았다. 대신 질문 길이 분포를 확인하고, 이후 분석에서 긴 질문의 영향을 검토할 수 있도록 원본 값을 유지했다.
할루시네이션 라벨의 불균형 확인
전체 데이터에서 할루시네이션이 발생한 Yes는 815개(약 18.1%), 발생하지 않은 No는 3,692개(약 81.9%)였다.
막대그래프를 통해 No 데이터가 Yes보다 훨씬 많다는 사실을 확인했다. 이러한 불균형은 이후 모델이 No를 지나치게 많이 예측하게 만들 수 있으므로, 학습 데이터와 시험 데이터를 나눌 때 두 집단의 Yes/No 비율을 유지하도록 설정했다.
질문 및 단어 군집화
질문의 의미적 특징을 분석하기 위해 TF-IDF를 이용하여 질문 속 단어의 중요도를 수치화하고, K-means 알고리즘을 사용하여 질문을 6개 군집으로 분류했다. 단어 역시 문맥적 특징을 바탕으로 8개 군집으로 구분했다.
다만 질문 군집의 분포를 분석한 결과, 학습 데이터 3,605개 중 2,017개(약 56.0%)가 하나의 군집에 집중되어 있었다. 이를 통해 처음 생성한 군집이 불균형하며, 더 세밀한 검토가 필요하다는 점을 확인했다.
또한 할루시네이션 발생 여부를 나타내는 Yes/No 라벨은 군집을 만드는 데 사용하지 않고, 군집별 특징을 분석할 때만 활용하도록 구분했다.

3. AI가 준 것 중 고치거나 버린 것과 그 이유
처음에는 분류되지 않는 질문들을 하나의 '기타' 군집으로 묶는 방안을 검토했지만, 이렇게 처리하면 서로 다른 특징을 가진 질문들이 하나의 범주에 포함되어 정보가 손실될 수 있다고 판단했다. 따라서 기존 군집을 다시 검토하고, 미분류 질문을 세분화하는 방향으로 수정했다.
또한 질문의 글자 수나 단어 수가 지나치게 크다는 이유만으로 해당 데이터를 제거하지 않았다. 실제로 긴 질문이 존재할 수 있으며, 이러한 질문 역시 할루시네이션 분석에 필요한 자료이기 때문이다.
원본 ID에 빈 값이 발견되었을 때도 해당 행을 삭제하지 않고 별도의 행 번호를 생성하도록 처리했다. 분석에 필요한 질문 데이터가 존재한다면 식별자 문제만으로 데이터를 제거할 필요는 없다고 판단했다.
마지막으로 Yes와 No의 데이터 수가 크게 다르므로, 단순한 정확도만으로 모델의 성능을 평가하는 방식은 적절하지 않다고 판단했다. 이에 따라 이후 모델 비교에서는 재현율, 정밀도, F1 점수 등의 지표도 함께 확인하기로 했다.

4. 느낀 점
처음에는 원본 데이터를 불러온 뒤 바로 군집화하면 된다고 생각했지만, 데이터를 분석하기에 적합한 형태로 바꾸는 과정이 중요하다는 것을 알게 되었다. **그리고 이 과정이 참 많이도 힘들었다.**  특히 원본에는 없던 질문의 길이와 단어 수를 수치화하면서, 같은 문장 데이터에서도 다양한 특징을 추출할 수 있다는 점이 흥미로웠다.
또한 결측치가 거의 없더라도 빈 값이나 이상치처럼 추가로 확인해야 할 요소가 존재한다는 것을 알게 되었다. 질문 군집을 생성한 뒤에는 특정 군집에 데이터가 집중되는 문제도 발견했는데, 이를 통해 알고리즘으로 분류한 결과가 항상 적절한 것은 아니며 통계적 검토가 필요하다는 점을 느꼈다.
앞으로는 군집을 단순히 세분화하는 데 집중하기보다, 실제로 할루시네이션 예측에 도움이 되는 특징인지 검증하면서 프로젝트를 진행하고 싶다.
