# 5차시 — 원본 데이터 전처리와 초기 군집화

> 2026-10-31에 진행한 연속 작업 중 첫 번째 단계의 기록이다.

## 1. 오늘 결정한 것

HaluEval 1.0의 general_data.json에서 사용자 질문의 특징을 추출하고, 회귀·분류 모델을 만들기 전에 질문과 단어를 먼저 군집화하기로 했다. 원본 4,507행·5열에서 질문 글자 수, 토큰 수, 고유 단어 수, 평균 단어 길이, 물음표·숫자 개수 등을 계산하여 4,507행·38열의 분석용 데이터로 만들었다. 원본 라벨은 Yes 815개(18.1%), No 3,692개(81.9%)였다.

질문 길이의 중앙값은 64자, 최댓값은 1,316자였지만 긴 질문이 실제 사용자 요청일 수 있으므로 삭제하지 않았다. 일반적인 결측값 집계는 0개였으나 원래 ID를 보관한 열에서 빈 값 1개가 확인되어 원본 행 순서를 나타내는 source_row로 식별했다. 같은 질문의 중복과 라벨 충돌을 확인했으며 최종적으로 제외된 질문은 없었다.

학습 3,605개와 시험 902개로 분리해 Yes/No 비율을 유지하고, 학습 질문에만 TF-IDF·차원 축소·K-means를 학습시켰다. 초기 질문군집 Q는 6개, 문맥 기반 단어군집 W는 8개로 설정했다. 군집을 만들 때 Yes/No 정답을 사용하지 않았으며 시험 세트는 이후 검증을 위해 보류했다.

| 기초 분석 | 확인 결과 |
| --- | ---: |
| 원본 → 전처리 후 | 4,507행·5열 → 4,507행·38열 |
| 질문 글자 수 평균 / 중앙값 | 약 75.95자 / 64자 |
| Yes / No | 815개 / 3,692개 |
| 학습 / 시험 분할 | 3,605개 / 902개 |
| 초기 질문군집 / 단어군집 | 6개 / 8개 |
| 가장 큰 초기 질문군집 | 학습 질문 2,017개(약 56.0%) |

기존 기록에 첨부했던 원본·전처리 데이터 비교 화면도 보존했다.

라벨 분포와 질문 길이 히스토그램을 살펴보니 클래스 불균형과 질문 길이 차이가 뚜렷했다. 특히 한 질문군집에 56%가 몰리는 현상은 초기 군집이 충분히 세분화되지 않았다는 근거가 되었다.

## 3. AI가 준 것 중 고치거나 버린 것과 그 이유

- 단순히 원본 ID를 그대로 식별자로 사용하는 대신, 빈 ID가 있어도 질문을 잃지 않도록 source_row를 사용했다.
- 긴 질문을 이상치라는 이유만으로 제거하는 방안은 채택하지 않았다. 질문 길이의 최댓값이 크다는 통계만으로 오류라고 판단할 수 없기 때문이다.
- 질문군집 6개가 자동으로 만들어졌다고 해서 의미별 분류가 완성됐다고 보지 않았다. 가장 큰 군집에 2,017개가 집중된 결과를 확인하고 다음 단계에서 재검토하기로 했다.

## 4. 느낀 점

처음에는 원본 데이터를 불러온 뒤 곧바로 군집화하면 될 것이라고 생각했지만, 실제로는 질문을 수치화하고 빈 값과 데이터 분포를 확인하는 데 시간이 많이 들었다. 그리고 이 과정이 참 많이도 힘들었다. 한 군집에 절반 넘는 질문이 모인 결과를 보며, 알고리즘을 실행했다는 사실만으로 좋은 분류가 완성되는 것은 아니라는 점을 알게 되었다.
