특히 두 번째 방법에서는 Sentence-BERT 같은 문장 임베딩 모델을 사용할 수 있어.

예를 들어 표현이 달라도 의미가 비슷한 두 질문을 가까운 위치에 배치하는 방식이지.

이렇게 만든 군집이 기존보다 실제 질문 유형을 잘 구분하는지 확인할 수 있어.

최종 판단
현재까지 밝혀낸 것은 두 가지야.

발견한 사실: 질문 군집 사이에 할루시네이션 발생률의 차이가 존재한다.

아직 해결하지 못한 문제: 그 차이만으로 새로운 질문의 할루시네이션 발생 여부를 정확히 예측하기는 어렵다.

그리고 마스터, 나는 오히려 이 결과가 탐구의 중요한 전환점이라고 생각해.

다음 단계에서는 TF-IDF보다 질문의 의미를 더 잘 반영하는 군집화 방법을 적용하고, 기존 결과와 비교하는 실험을 추천해.

그러면 단순히 군집화하는 것으로 끝나는 게 아니라, 어떤 전처리 방식이 실제 할루시네이션 예측에 도움이 되는지 검증하는 연구로 발전시킬 수 있어.

군집에 라밸을 붙여줄 수 있어? 무슨 차이가 있는지 구별하기가 힘든데
물론이지, 마스터. 실제로 각 군집에 포함된 질문들을 확인해서 6개 군집에 임시 라벨을 붙여봤어.

그런데 확인해 보니 문제가 하나 있어. 현재 군집들은 질문의 주제보다는 Create, Generate, List처럼 AI에게 요구하는 작업의 표현을 중심으로 구분되는 경향이 강해.

이건 현재 군집의 이름을 바꾸는 작업이 아니라 새로운 분류 기준을 설계하는 작업이야. 하나의 질문이 여러 유형에 속할 가능성도 고려해야 하고.

내 생각에는 마스터가 원했던 것이 단순히 Create와 Generate의 차이를 분석하는 것은 아닐 거야.

질문이 어떤 정보를 요구하는지에 따라 할루시네이션 발생률이 달라지는지 알아보려는 거잖아.

그렇다면 현재 군집에는 위의 임시 라벨을 붙여 두고, 다음에는 질문의 의미와 요구하는 정보의 성격을 중심으로 군집화를 개선하는 방향을 추천해.



내가 최종적으로 원하는건 사용자가 프롬포트를 입력할 때 이 질문이 할루시네이션을 일으켜 사용에 장애가 생기는 걸 막는 거잖아.
네가 말한 구체화된 연구 질문을 최종적인 프로젝트의 중간과정으로 둘 순 없나?
데이터를 추가로 구해도 되는 일이고
마스터, 그 말이라면 이야기가 완전히 달라지지.

그렇다면 우리가 지금까지 진행한 연구는 방향이 잘못된 게 아니라, 최종 목표에 도달하기 위한 첫 번째 연구 단계였던 거야.

오히려 나는 지금 네가 설명한 최종 목표가 훨씬 좋은 프로젝트라고 생각해.

앞서 내가 연구 방향을 지나치게 단어 분석에 한정해서 판단했어. 네가 만들려는 건 단순한 데이터 분석 모델이 아니라 AI가 잘못된 정보를 생성할 위험을 사전에 감지하고, 그 위험을 낮춰주는 시스템이었던 거지.

그렇다면 프로젝트 전체를 다시 설계해보자.

③ 예방 조치

질문 수정 제안, 근거 자료 검색, 모호한 조건 확인

④ 생성된 답변 검증

근거가 부족하거나 확인되지 않은 주장 표시

여기서 중요한 점이 있어.

질문만 분석해서는 할루시네이션 발생을 확정할 수 없어. 같은 질문이라도 어떤 AI 모델이 답변하는지, 어떤 자료를 참고하는지에 따라 결과가 달라지니까.

그래서 나는 입력 전 위험 예측과 출력 후 사실 검증을 결합하는 방식을 추천해.

개별 단어보다 단어의 의미적 유형과 조합을 분석했을 때, 할루시네이션 발생 여부를 더 정확하게 예측할 수 있을까?
이 연구는 최종 시스템을 구성하는 위험 예측 모델의 성능을 개선하는 과정이 되는 거지.

3. 추가 데이터는 어떻게 활용하면 좋을까?

4. 프로젝트의 전체 연구 순서
나는 앞으로 프로젝트를 다음 네 단계로 진행할 것을 추천해.

01
할루시네이션과 연관된 프롬프트 특징 분석

현재 상당 부분 진행됨
단어 빈도, 질문 유형, 단어 조합 등을 조사하고 어떤 특징이 예측에 도움이 되는지 검증해.

02
프롬프트 위험 예측 모델 제작

다음 연구 단계
TF-IDF 기반 로지스틱 회귀와 군집 특징을 추가한 모델을 비교하고, 학습에 사용하지 않은 질문으로 성능을 검증해.

03
할루시네이션 예방 기능 제작

시스템 구현 단계
위험 신호에 따라 질문을 명확하게 바꾸도록 제안하고, 사실 확인이 필요한 질문에는 신뢰할 수 있는 근거 자료를 제공해.

04
예방 효과 실험 및 최종 시스템 완성

최종 검증 단계
같은 질문을 예방 기능 적용 전후로 AI에 입력해 답변의 오류 발생률을 비교해. 모델, 평가 기준, 생성 조건을 통제해서 실제 개선 여부를 측정하는 거야.

5. 내가 특히 강조하고 싶은 실험
마스터, 사실 나는 마지막 실험이 이 프로젝트에서 가장 중요하다고 생각해.

왜냐하면 위험을 잘 예측하는 모델과 실제로 할루시네이션을 줄이는 시스템은 서로 다른 문제이기 때문이야.

예를 들어 위험 예측 정확도가 높아도, 사용자가 질문을 수정한 뒤 여전히 틀린 답변을 받는다면 최종 목표를 달성했다고 보기 어렵겠지.

프로젝트 제목을 붙인다면 이런 식이 좋겠네.

「프롬프트의 언어적 특징 분석을 통한 대규모 언어모델의 할루시네이션 위험 예측 및 예방 시스템 개발」

이 제목 안에 우리가 하려는 작업이 모두 들어가 있어.

언어적 특징 분석: 단어 군집화와 단어 조합 연구

위험 예측: 로지스틱 회귀와 기계학습

예방 시스템: 질문 개선 및 근거 확인

효과 검증: 예방 기능 적용 전후 비교

그리고 지금 당장 우리가 진행해야 하는 작업도 명확해졌어.

먼저 기존 HaluEval 데이터로 프롬프트 위험 예측 모델을 완성하고, 현재 약 0.665인 ROC-AUC를 기준으로 단어 유형·조합 정보가 성능을 얼마나 개선하는지 검증하자.

추가 데이터는 모델의 한계를 확인하고 예방 기능을 개발하는 과정에서 단계적으로 도입하면 돼.

지금까지 했던 작업도 충분히 가치가 있어. 다만 이제부터는 새로운 군집을 하나 만들 때마다 그것이 최종 예방 시스템에 어떤 도움을 주는지 확인하면서 진행하자.

그렇게 하면 연구가 다시 산으로 갈 일은 훨씬 줄어들 거야.

마스터, 이제 정확히 이해했어.

그렇다면 프로젝트의 중심을 다시 잡을 필요가 있어.

내 결론부터 말하자면, 현재 프로젝트의 주제와 데이터는 적절하지만, 분석 방법과 연구 범위는 조정하는 게 좋겠어.

7. 프로젝트에서 프로그램은 어느 정도로 구현하면 될까?

최종 Streamlit 웹앱에 다음 기능을 제공하는 정도면 충분히 의미 있다고 생각해.

사용자가 질문을 입력한다.

질문의 글자 수와 단어 수를 분석한다.

질문에 포함된 단어 유형을 표시한다.

관찰된 데이터에 근거한 위험 추정값과 한계를 안내한다.

어떤 단어나 조합이 예측에 영향을 주었는지 보여준다.

최종적으로 방지 효과까지 주장하려면, 위험한 프롬프트를 수정했을 때 실제 LLM 응답의 할루시네이션이 줄어드는지 별도로 실험해야 해.

그것까지 포함하면 프로젝트의 완성도가 더 높아질 거야.

5. 내 최종 판단
마스터, 나는 지금이 탐색적 데이터 분석을 마무리하기에 거의 적절한 시점이라고 생각해.

우리는 이미 다음을 확인했어.

질문 유형에 따라 할루시네이션 비율이 달라진다.

단어의 의미적 유형을 이용하면 질문을 더 세분화할 수 있다.

일부 교차 군집에서 발생 비율의 차이가 발견된다.

그러나 군집을 세분화한다고 반드시 예측 성능이 좋아지는 것은 아니다.

현재는 TF-IDF를 활용한 모델이 가장 좋은 예측 성능을 보인다.

이 다섯 가지는 하나의 데이터 과학 프로젝트에서 충분히 중요한 분석 결과야.

내 추천은 '마지막 개선 실험 1회 → 군집 확정 → 최종 모델 검증'이야.

언제까지나 더 좋은 군집이 나올 거라고 기대하며 데이터를 파고들 수는 없어.

그리고 무엇보다 중요한 건, 우리가 얼마나 많은 군집을 만들었느냐가 아니라 데이터에서 발견한 사실을 바탕으로 실제 문제를 얼마나 해결할 수 있느냐잖아?

그걸 이제 확인해 볼 때가 온 거야.

오케이 그럼 방금전 에 제안했던 방안으로 개선 한번만 더 진행해보자
마스터, 약속했던 마지막 군집 개선 실험을 완료했어.

K-Means: 의미나 사용 문맥이 비슷한 질문·단어를 군집화
