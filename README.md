## 질문

> **질문의 단어적 특징은 정말 AI의 할루시네이션 발생을 예측하는 단서인가?**

## 왜 이 주제인가 (직접 작성한 내용으로 최종 검토)

나는 AI 개발자를 진로로 희망하고 있으며, 생성형 AI가 자연스럽고 그럴듯한 답변을 제시하더라도 그 내용이 항상 사실인 것은 아니라는 점에 관심을 갖게 되었다. 특히 AI의 답변을 확인하기 전에 **사용자가 입력한 질문의 길이, 단어, 표현, 주제만으로 할루시네이션 발생 위험을 미리 알 수 있을까?**라는 의문이 생겼다. 이를 실제 데이터와 머신러닝으로 검증해 보고자 HaluEval 데이터를 선택했다. 단순히 점수가 높은 모델을 만드는 것을 넘어, 예측할 수 있는 정보와 예측하기 어려운 정보의 경계를 직접 확인하는 것을 목표로 삼았다.

## 방법

**선택한 방법: 분류**

최종적으로는 질문을 입력받아 **할루시네이션 발생 가능성(0~1의 예측 확률)**을 계산하고, 이를 **0.5 이상이면 Yes, 미만이면 No**로 판정하는 이진 분류를 중심으로 평가했다. 이름에 ‘회귀’가 들어가지만 **로지스틱 회귀는 이진 분류 모델**이며, 연속적인 확률도 출력한다. 앞서 진행한 **군집화는 최종 판정 모델이 아니라 질문의 특성을 만드는 전처리**로 활용했다.

### 분석 과정: 무엇을·어떻게·왜 진행했는가

1. **데이터 수집:** HaluEval 1.0의 `general_data.json`에서 질문·AI 답변·Yes/No 판정을 확인하고, 실제 분석 대상 4,507개를 정리했다. 질문의 표현과 오류 여부의 관련성을 분석하기 위해서다.
2. **변수 선택:** 정답 `y`를 제외한 **질문 텍스트, 글자 수, 단어 수, 질문 유형, 군집 특징** 등을 입력 변수로 선택했다. 답변 생성 전의 질문만으로 예측한다는 연구 조건을 지키기 위해 AI 답변 자체는 입력하지 않았다.
3. **전처리:** 텍스트를 TF-IDF(기본 단어·2단어 조합, 최대 1,200개 특징, `min_df=3`)로 수치화하고 질문 수치형 변수는 결측값 보정·표준화를, 범주형 변수는 원-핫 인코딩을 적용했다. 질문군집 **Q0~Q5(6개)**와 단어군집 **W0~W7(8개)**도 별도로 분석하고 입력 특징으로 사용할 수 있도록 정리했다. 초기 군집이 한곳에 쏠리는 현상이 있어 재군집화·의미 그룹 세분화·교차군집화도 시험했지만, 최종 예측에 유익한지는 별도로 검증했다.
4. **분할:** 저장된 분할을 그대로 사용해 **학습 3,605개 / 시험 902개**, 난수값 **42**로 유지했다. 학습 자료에서 **5겹 교차검증**을 수행하고 TF-IDF와 인코더도 각 훈련 부분에서 학습시켜 시험 정답이 전처리에 섞이지 않도록 했다.
5. **기준선 설정:** 언제나 **No**라고 답하는 ‘다수 범주 찍기’를 분류 기준선으로 두었다. 확률 예측의 추가 기준선으로는 **학습 데이터의 Yes 비율 18.09%를 모든 질문에 동일하게 출력하는 평균 확률 모델**도 사용했다.
6. **후보 모델 비교:** **선형 회귀, 로지스틱 회귀, 의사결정트리**를 같은 데이터와 분할로 비교했다. 선형 회귀는 확률 범위를 벗어나는 예측의 한계를 확인하기 위한 비교 대상이고, 로지스틱 회귀와 의사결정트리는 분류 모델이다. 앞선 탐색 단계에서는 kNN·랜덤 포레스트 등도 시험했으나 최종 비교표는 위 세 모델로 정리했다.
7. **모델 선택:** 원래 프로젝트의 위험도 수치 예측 목적에 따라 **학습 5겹 교차검증 Brier 점수가 가장 낮은 ‘로지스틱 회귀 + 군집 특징’**을 최종 비교 대상으로 정했다. 단, Brier가 우수하다는 사실이 Yes/No 판정 성능까지 좋다는 뜻은 아니므로 분류 지표를 별도로 분석했다.
8. **평가:** 고정 시험 데이터 **902개**에 대해 기준 **0.5**로 정확도·정밀도·재현율·F1·혼동행렬을 계산했다. 확률의 품질을 보조적으로 확인하기 위해 PR-AUC(AP), ROC-AUC, Brier도 함께 검토했다.
9. **해석:** **항상 No인 기준선보다 정확도가 높지 않고, 실제 Yes 대부분을 놓쳤다는 점**에 주목했다. 군집 ON/OFF와 성능 개선 실험의 결과도 함께 비교했다.
10. **한계 점검:** 데이터 불균형, 원래 라벨이 특정 AI 응답에 의존한다는 점, 시험 데이터 하나에서 관찰한 수치를 다른 AI·새로운 질문에 일반화하기 어렵다는 점을 구분해 기록했다.

## 결과 해석

### 사용한 평가 지표와 수치

**최종 로지스틱 회귀 + 군집 ON, 시험 902개, 판정 기준 0.5**

| 지표 | 수치 | 뜻 |
|---|---:|---|
| 정확도(Accuracy) | **81.37%** | 전체 902개 중 맞춘 비율 |
| 정밀도(Precision) | **35.29%** | Yes로 경고한 17개 중 실제 Yes인 비율 |
| 재현율(Recall) | **3.68%** | 실제 Yes 163개 중 찾아낸 비율 |
| F1 | **0.0667** | 정밀도와 재현율의 조화평균 |
| PR-AUC(AP, Average Precision) | **0.3134** | Yes를 높은 위험도로 구분해 순위를 매기는 성능 |
| ROC-AUC | **0.6922** | 임의의 Yes가 No보다 더 높은 위험도를 받을 가능성에 관한 순위 성능 |
| Brier 점수 | **0.1393** | 실제 0/1 정답과 예측 확률의 평균 제곱오차(낮을수록 좋음) |

**혼동행렬(시험 902개)**

| 실제 \ 예측 | No | Yes |
|---|---:|---:|
| 실제 No (739개) | TN **728** | FP **11** |
| 실제 Yes (163개) | FN **157** | TP **6** |

즉, **실제 할루시네이션이 있었던 163개 중 6개만 찾아내고 157개를 놓쳤다.**

### 기준선과 비교하면

| 지표 | 다수 범주 기준선(항상 No) | 로지스틱 회귀 |
|---|---:|---:|
| 정확도 | **81.93%** | 81.37% |
| 정밀도 | 0% | 35.29% |
| 재현율 | 0% | **3.68%** |
| F1 | 0 | 0.0667 |
| 찾아낸 Yes | 0개 | **6개** |
| 놓친 Yes | 163개 | **157개** |
| 시험 Brier(평균 확률 기준선) | 0.1481 | **0.1393** |

정확도만 보면 **무조건 No라고 답하는 모델(81.93%)이 로지스틱 회귀(81.37%)보다 오히려 높다.** 로지스틱 회귀는 확률 오차(Brier)를 약간 줄였지만, 실제 Yes를 경고하는 분류 성능은 충분하지 않았다.

### 이 결과가 뜻하는 것: 나의 해석

최종 결과는 **질문의 단어적·형식적 특징만으로 할루시네이션 발생을 실질적으로 신뢰할 수준으로 예측하지 못했다**는 것이다. 확률 점수에는 일부 통계적 신호가 있었지만, 0.5 기준 분류에서는 Yes 대부분을 놓쳤다. 따라서 “전혀 상관이 없다”거나 “어떤 AI에 대해서도 불가능하다”고 단정할 수는 없지만, **이번 데이터와 모델로 만든 사전 경고 시스템은 실용적인 성능을 확보하지 못했다**고 판단했다.

### 내가 찾아낸 인사이트 3개

1. **헤드라인: 정확도 81%가 좋은 모델을 뜻하지는 않았다.**  
   **근거 수치:** 전체 Yes 815/4,507(18.08%); 시험 기준선 정확도 **81.93%**, 로지스틱 회귀 **81.37%**.  
   **뜻:** No가 많은 불균형 데이터에서는 대부분을 No라고 판단해도 높은 정확도가 나온다.  
   **상식과 다른 점:** 정확도가 80%를 넘더라도 정말 찾아야 하는 오류를 대부분 놓칠 수 있다.

2. **헤드라인: 할루시네이션을 찾아내는 능력은 예상보다 훨씬 낮았다.**  
   **근거 수치:** 실제 Yes **163개 중 TP 6개, FN 157개**, 재현율 **3.68%**, F1 **0.0667**.  
   **뜻:** 질문만 보고 위험을 경고하는 방식으로 사용하기에는 탐지 능력이 부족했다.  
   **상식과 다른 점:** 확률 오차가 기준선보다 낮아도 실제 Yes/No 분류가 유용하다는 뜻은 아니다.

3. **헤드라인: 군집을 더 세밀하게 만들거나 설정을 바꾼다고 예측력이 자동으로 향상되지는 않았다.**  
   **근거 수치:** 로지스틱 회귀 시험 Brier **군집 OFF 0.139384 / ON 0.139318**, 차이 약 **0.000066**. 규제 강도 C=0.3 설정에서는 학습 CV Brier가 **0.140781 → 0.140086**으로 개선됐지만 시험 Brier는 **0.139318 → 0.140149**로 악화됐다.  
   **뜻:** 군집의 의미적 세분화와 학습 점수의 개선은 실제 새 데이터 예측 성능 향상을 보장하지 않는다.  
   **상식과 다른 점:** 변수를 더 늘리거나 군집을 복잡하게 만드는 방식이 반드시 더 좋은 모델을 만들지는 않는다.

### 성능 개선 과정 요약

두 차례에 걸쳐 **TF-IDF 표현 범위 조정, Yes 가중치 부여, 의사결정트리 가지치기, 로지스틱 회귀 규제 강도 C 조정, 시그모이드/아이소토닉 확률 보정, 질문 의미 단서 추가**를 시험했다.

- TF-IDF 확대: CV Brier **0.140781 → 0.140506**, 시험 Brier **0.139318 → 0.139498**로 악화.
- Yes 가중치 1.5배: 시험 재현율 **3.68% → 12.88%**로 상승했지만 시험 Brier **0.139318 → 0.143374**로 악화, 잘못된 경고 **11 → 34개**.
- 트리 가지치기 강화: 트리 시험 Brier **0.150262 → 0.149613**으로 개선됐지만 평균 확률 기준선 0.148054보다 높음.
- 로지스틱 회귀 C=0.3: CV Brier **0.140086**, 시험 Brier **0.140149**.
- 시그모이드 확률 보정: CV Brier **0.140159**, 시험 Brier **0.139663**.
- 질문의 사실 관련 표현 4개 추가: 시험 Brier **0.139103**으로 소폭 낮아졌지만 CV Brier **0.140955**로 기존보다 높음.

**결론:** 일부 지표에서 개선이 나타났지만 **교차검증과 시험 데이터 양쪽에서 일관되게 우수한 개선안을 확보하지 못했다.** 특정 시험 결과만 보고 최종 모델을 바꾸지 않았다.

## 한계

### 이 결과를 믿기 어려운 이유(수치로)

- **불균형:** 전체 4,507개 중 Yes **815개(18.08%)**. No가 다수여서 정확도가 과대평가되기 쉽다.
- **낮은 탐지율:** 재현율 **3.68%**, 놓친 Yes **157/163개(96.32%)**.
- **기준선 대비 불리한 정확도:** 로지스틱 **81.37%** < 항상 No 기준선 **81.93%**.
- **미미한 군집 효과:** 시험 Brier의 군집 ON/OFF 차이는 약 **0.000066**.
- **한정된 조건:** 데이터셋에는 특정 AI 응답에 붙인 Yes/No 라벨이 있으며, 다양한 최신 AI·질문 환경에서 성능을 별도로 검증하지 않았다.

### 이 결과를 잘못 쓰면 생길 수 있는 일

모델이 **No**라고 판단한 질문을 안전하다고 믿고 AI 답변의 사실 확인을 생략하면, 실제 할루시네이션을 놓칠 수 있다. 반대로 Yes 경고를 과도하게 신뢰하면 정상적인 답변이나 유용한 질문까지 부당하게 위험하다고 판단할 수 있다. **이 모델은 AI 답변의 진위를 판정하는 도구가 아니라 연구 목적의 탐색적 예측 실험**이다.

## 더 해 보고 싶은 것 (교과 연계 · 진로)

- **교과 연계:** 수학의 확률과 통계·함수, 데이터 과학의 전처리·군집화·머신러닝 모델 평가, 정보의 텍스트 데이터 처리와 연결했다. 특히 조건부 확률, 불균형 데이터의 평가 지표, 손실 함수와 일반화 오차가 이번 탐구를 이해하는 핵심 개념이었다.
- **진로 분야:** **인공지능·소프트웨어 개발 및 AI 엔지니어링**. 앞으로 질문 외에 **AI 답변 내용, 검증 가능한 외부 근거, 다양한 언어모델**까지 함께 사용해 할루시네이션의 발생을 더 신뢰성 있게 감지하는 방법을 연구하고 싶다.

## 느끼고 배운 점 (AI 활용 · 데이터 분석)

처음에는 질문을 단어로 나누고 군집을 만들면 오류가 발생하기 쉬운 질문을 비교적 쉽게 알아낼 수 있을 것이라고 생각했다. 그러나 실제로는 한 군집에 질문이 지나치게 몰리거나, 군집의 품질 지표가 나아져도 예측 모델의 성능이 개선되지 않는 일이 있었다. 또한 정확도가 높아 보여도 항상 No를 선택하는 기준선보다 좋지 않다는 점을 확인하면서 **지표는 숫자 자체보다 데이터의 분포와 연구 목적에 맞춰 해석해야 한다**는 것을 배웠다.

성능 개선 실험에서도 어떤 설정은 교차검증 성능만 좋아지고 시험 성능은 나빠졌다. 이 결과를 통해 좋은 점수만 선택해 발표하는 대신 **실패한 시도와 모델의 한계도 함께 기록하는 것이 데이터 분석 과정에서 중요하다**고 느꼈다. AI의 도움으로 코드를 구성했지만, 연구 질문을 다시 설정하고 군집을 전처리로 활용할지 결정하며 페이지 오류를 지적하는 과정에는 나의 판단이 필요했다. 이번 탐구의 최종 성과는 높은 정확도의 모델을 얻은 것이 아니라, **질문만으로 할루시네이션을 미리 판단하는 방법이 왜 어려운지 실제 수치로 설명하게 된 것**이다.

## 생성형 AI 활용 명시

- **사용한 생성형 AI:** OpenAI **ChatGPT (이 README 작성 환경: GPT-6)**. 이전 대화 및 초기 실험 전체에서 실제 사용된 모델 버전은 기록만으로 일괄 확인할 수 없으므로 모두 GPT-6를 썼다고 주장하지 않음.
- **사용한 곳:** Python·Streamlit 코드 작성과 수정, 원본 및 가공 데이터 분석 보조, TF-IDF·군집화·예측모델 비교, 평가 지표 계산, 결과 시각화, 성능 개선 실험 구성, GitHub 파일 정리, 문서 초안 작성.
- **AI를 최종 판단 근거로 사용하지 않은 곳:** 연구 질문과 분석 방향 선택, 군집은 예측을 위한 전처리라는 판단, 최종 비교 모델 지정, Yes를 놓치는 문제의 중요성 판단, 실험 결과를 과장하지 않고 마무리하겠다는 결정.
- **검증 방법:** GitHub에 저장된 실제 CSV·JSON 수치와 비교, 학습/시험 분할 및 5겹 교차검증 조건 확인, 혼동행렬의 네 숫자 합계가 시험 질문 902개와 일치하는지 확인, 기준선과 모델의 지표 비교, Python 문법 및 파일 경로 확인. **배포된 Streamlit 앱의 모든 화면을 직접 실행·검증했다고 주장하지 않음.**
- **AI 없이 내가 한 일과 구분:** 나는 연구 방향과 보완 요구를 제시하고 오류를 발견·수정 요청했다. 코드 작성·재학습 실행·수치 산출에는 AI의 도움을 받았다.
